1. Arsitektur Sistem & Prinsip Keselamatan

Hardware & Protokolv3.1.0

Shoto ↔ Samoto Bridge adalah penerjemah protokol BMS dual-UART berbasis ESP32 FreeRTOS antara bank baterai lithium Shoto SmartLi / 01-SD-BA430 (15S LFP, 48 V / 100 Ah per pack, tanpa DIP switch) dan inverter hybrid Samoto IHF6200 / ILS6300 / ILS3600 memakai protokol Pylontech LV RS485 (V3.5 & V3.3).

3 Pilar Keselamatan Wajib
  1. 100% Read-Only ke BMS Shoto: Firmware ESP32 dan Home Assistant tidak pernah menulis ke register/EEPROM Shoto dan tidak pernah mengirim wakeup 16× 0xAA setelah terkunci di PROTO_TBD_BINARY.
  2. Inverter Tetap Prioritas Utama: Task RS485 inverter berjalan terisolasi di Core 1 (prioritas 3). Jika Wi-Fi, Mosquitto, atau Mini PC HA mati, komunikasi bridge ↔ inverter tetap berjalan normal.
  3. Fail-Closed Safety: Data baterai basi (> 9000 ms), selisih tegangan pack terlalu lebar (> 1.0 V), 0 pack online, atau proteksi kritis memicu INHIBIT (CCL=0 A, DCL=0 A).

  • Di solar.siseli.com saat auto-switch ke PLN: battery voltage = 52.1 V, battery capacity = 0%, battery status = charge, battery type = PYL, battery charge current = 0 A, error inverter kode = 4.
  • Di HA View 1 (2026-11-26 21:26 WIB): Mode Inverter = PYL_FULL, Protokol = TBD_BINARY, Kapasitas = 299.0 Ah, CCL = 90.00 A, DCL = 120.00 A, Raw SOC = 68.5%, Bank Valid = On (sudah pulih), Alasan Inhibit = CRITICAL.
  • Bukti 4 Screenshot Histori HA (`2026-11-27` pagi): Ketiga pack secara bergantian mengalami lonjakan sesaat ke prot_flags = 4 (0x0004 = Cell UV Prot min_cell_mv <= 2550 mV) hanya selama 1 siklus poll (~3 detik) lalu langsung pulih ke 0:

    • Pack 2: 0 → 4 pada 05:35:56 AM → kembali 0 pada 05:35:59 AM (3 detik).
    • Pack 1: 0 → 4 pada 06:08:41 AM → kembali 0 pada 06:08:44 AM (3 detik).
    • Grafik Pack 1/2/3 Cell Min (03:09–06:08 AM): Ketiga pack sangat sehat & rata lurus di ~3.260–3.290 mV (saat capture 3.323–3.327 mV), lalu muncul 1 jarum vertikal tajam 1-sampel di ~06:04 AM di mana Pack 1 Cell Min jatuh dari ~3.265 mV ke ~2.250 mV (-1.015 mV) dan langsung kembali ke ~3.265 mV sementara Pack 2 & Pack 3 pada bus DC yang sama tetap rata. Penurunan 1,015 V ini masih lolos cek keutuhan jumlah sel (< 3,0 V di bridge_protocols.hpp:438), lalu langsung memicu min_cell_mv <= 2550 mV (prot_flags = 4).
    • Catatan sekunder: terlihat juga Unavailable singkat pada 02:38–02:39 AM (restart singkat ESP32 yang sempat me-reset Alasan Inhibit ke NONE di 02:39:26 AM sebelum Pack 3 = 4 pukul 03:09:44 AM memicunya lagi) dan reconnect MQTT 10 detik pada 09:29:00–09:29:10 AM.
  • Mengapa Glitch 3 Detik Ini Mengunci Inverter ke PLN? Fisik sel LFP 100 Ah tidak mungkin drop 1 V lalu pulih sempurna 3 detik kemudian di paralel bus yang sama — ini murni glitch 1-frame pembacaan AFE/balancing internal Shoto SD-BA430. BMS Shoto sendiri mengabaikan glitch ini karena EEPROM-nya memiliki Cell UV Alarm Delay = 3000 ms & Cell UV Prot = 2000 mV, sedangkan firmware ESP32 sebelumnya hanya memiliki retry konfirmasi untuk INHIBIT_DELTA_V, belum untuk INHIBIT_CRITICAL.
  • Perbaikan Firmware SUDAH DITERAPKAN & TERVERIFIKASI Host (`bat_poll_task` & `bridge_protocols.hpp`):
    1. Anti-Glitch 1× Re-Poll Konfirmasi (`shoto_samoto_bridge.ino`): Saat pack_needs_prot_recheck() mendeteksi prot_flags != 0, critical, atau pembatasan charge/discharge, ESP32 menunggu 150 ms lalu mem-poll ulang hanya slot pack terkait sebelum memublikasikan status ke g_bank/inverter. Glitch 1-frame AFE tersaring diam-diam dan tercatat pada counter Serial CLI protRetry=OK/FAIL (perintah status / diag).
    2. Directional OV/UV Protection (`bridge_protocols.hpp`): Jika kondisi nyata tetap bertahan setelah re-poll, Cell OV (>= 3650 mV soft / >= 3750 mV prot) atau Pack OV (>= 56.5 V) memblokir Charge saja (CCL = 0 A, 63H = 0x40, tetap izinkan Discharge & kirim SOC asli tanpa Error 04); sedangkan Cell UV (<= 2550 mV) atau Pack UV (<= 40.5 V) memblokir Discharge saja (DCL = 0 A, 63H = 0x80, tetap izinkan Charge PLN/PV). Gangguan termal ekstrem (OT >= 65 °C / UT <= -10 °C) atau konflik OV+UV tetap memicu INHIBIT_CRITICAL fail-closed penuh. (Catatan: re-flash ESP32 untuk mengaktifkan perbaikan ini secara live.)

Mengapa aturan manual 46 V Return To Mains Voltage tidak terpakai? Karena pada mode Menu 05 = PYL, inverter mengikuti SOC (%) & izin 63H dari BMS. Begitu kapasitas terbaca 0%, inverter langsung memicu Error 04, pindah ke PLN, dan menahan charging 0 A — lalu dapat terkunci di PLN hingga memenuhi BMS Returns To Battery Mode SOC (tercatat 90% pada capture Siseli sebelumnya).

Kecocokan 1:1 dengan Jalur Kode Firmware Bridge

Kombinasi 52.1 V + 0% + charge 0 A + Error 04 cocok persis dengan salah satu dari 2 kondisi berikut:

Kondisi A — Firmware ESP32 masuk INHIBIT (bank.core.valid == false)

Di bridge_protocols.hpp (baris 1250–1270 & 1331), saat INHIBIT aktif, bridge tetap membalas inverter dengan:

  • 61H: tegangan asli (52.1 V), tetapi SOC = 0% dan arus 0 A.
  • 63H: CCL = 0 A, DCL = 0 A, Allow Charge = No, Allow Discharge = No (0x00) → membuat battery charge current = 0 A.
  • 62H: bit System Fault ON (p2 |= 1 << 3).

Perhatikan tegangan 52.1 V (zona puncak LFP 15S): di zona ini ada 3 pemicu INHIBIT paling mungkin:

  1. INHIBIT_CRITICAL — ada 1 sel melonjak >= 3750 mV saat charging (bridge_protocols.hpp baris 456–463).
  2. INHIBIT_DELTA_V — selisih tegangan antar 3 pack > 1,0 V (misalnya 1 pack lebih dulu penuh / cut-off MOSFET charge).
  3. INHIBIT_STALE — salah satu pack gagal dibaca > 9000 ms.
Kondisi B — Komunikasi RS485 Inverter ↔ ESP32 terputus / timeout (BMS Communication Normal = No)

Di mode PYL, bila inverter berhenti menerima balasan 61H/63H (mis. Bridge Mode = MONITOR_ONLY, Inv Mutex Miss > 0, kabel RS485 longgar, atau ESP32 reboot brownout), inverter tetap membaca tegangan terminal DC (52.1 V), menjatuhkan battery capacity ke 0%, memunculkan Error 04, dan menahan charge current = 0 A.

3. Audit Timing Module Bridge (`bat_poll`, `inv_bridge`, `ha_mqtt`)

Diagnosa & ErrorCode Trace Verified
  • Sisi Inverter (inv_bridge_task, Core 1, Prio 3): Pada kondisi sehat tidak ada miss timing. Poll RS485 dicek tiap 2 ms, waktu proses < 6 ms + waktu kirim kabel 9600 baud 27–127 ms, sementara IHF6200 mengirim request tiap 170–212 ms (data/ihf6200_raw.log).
  • Siklus Baca 3 Pack (bat_poll_task, Core 0, Prio 2): Normalnya ~2,2–2,9 detik (POLL_INTERVAL_MS = 1500 ms + 3 pack + 1 probe slot offline 320 ms tiap 5 detik), masih jauh di bawah batas POLICY_FRESHNESS_MS = 9000 ms.
  • Celah Timing Saat Miss / Gangguan:
    • Setiap pack miss pada PROTO_TBD_BINARY menunggu 0x7C 500 ms + 0x7E 500 ms = 1000 ms. Bila banyak miss beruntun + audit EEPROM params, umur sampel dapat melewati 9000 ms → memicu INHIBIT_STALE (kirim SOC = 0%).
    • inv_bridge_task hanya menunggu g_snap_mutex maksimal 10 ms (shoto_samoto_bridge.ino:1131). Jika mutex tertahan > 10 ms, reply di-drop dan counter mtxMiss naik.
    • Aktifnya Wi-Fi (ENABLE_HA_MQTT = 1) menambah lonjakan arus TX 250–400 mA; catu daya lemah berisiko brownout reboot ~3 detik.

4. Audit Gap Daya Bank ±100 W & Parameter Lain (HA vs LCD Inverter)

Audit & ParameterFisika vs Delay

Di ha_mqtt_codec.hpp:490 dan bridge_protocols.hpp:1181-1183, daya bank HA dihitung langsung dari terminal DC baterai: P_HA = V_avg × (I_P1 + I_P2 + I_P3).

Kesimpulan Audit: Utamanya BUKAN Timing Delay, melainkan Beda Titik Ukur DC vs AC (~60–120 W)
  1. Titik ukur berbeda (DC baterai vs AC Output Load): Inverter IHF6200 (6,2 kW) memiliki self-consumption sekitar 50–75 W (board kontrol, IGBT/MOSFET, kipas, LCD, dongle Wi-Fi) ditambah rugi konversi DC→AC ~7–10%. Pada beban AC 500 W, baterai menyuplai ~598 W (gap ~+98 W di HA saat discharge).
  2. Zero-offset shunt paralel 3 pack (±20–50 W): Penjumlahan toleransi sensor arus masing-masing BMS (mis. ±0,3 A × 3 = ±0,9 A × 50 V ≈ ±45 W).
  3. Timing delay sekunder (~2,5–5,5 detik): POLL_INTERVAL_MS = 1500 ms + baca berurutan 3 pack + HA_TELEMETRY_INTERVAL_MS = 3000 ms hanya memberi beda sesaat saat beban baru berubah mendadak; saat beban diam > 15 detik, gap konstan ~100 W adalah rugi inverter + shunt (normal).

7. Home Assistant: 212 Entitas MQTT, Gate Keamanan & Penyebab No Entity

Home Assistant & MQTT212 Entities / Site
  • Mengapa sempat muncul semua kartu dashboard no entity? Karena versi awal dashboard memanggil prefix entity *_shoto_ils6300_*, sedangkan ESP32 yang aktif sudah memakai HA_DEVICE_ID = "shoto_ihf6200". Setelah dashboard diperbarui memakai shoto_ihf6200_*, seluruh 212 entitas langsung cocok 1:1.
  • Struktur 212 Entitas per Site (ha_mqtt_codec.hpp): 64 entitas global + 4 × 37 = 148 entitas per-pack (17 status/sel min-max-dV/EEPROM valid + 5 suhu + 15 tegangan sel individu), dicetak oleh writer JSON statis snprintf (batas HA_MQTT_MAX_PAYLOAD = 1400 B, bebas heap fragmentation).
  • Keamanan Aksi 2-Langkah: Kontrol sensitif (Bridge Mode, Dynamic Pack Discovery, slider CVL/DVL/CCL/DCL/Max dV, Reset Policy, Restart ESP32) disembunyikan oleh kartu conditional di View 4 sekaligus ditolak keras di ESP32 (HA_ACT_DENIED_LOCKED) jika switch Maintenance Unlock tidak ON (auto-relock 300 s). Setting disimpan persisten di NVS namespace "shoto_ha" dengan hard-clamp LFP 15S.
  • Optimasi SSD Mini PC: configuration.yaml menyetel purge_keep_days: 30, commit_interval: 15, serta mengecualikan frame hex mentah tinggi frekuensi sensor.*_diag_tx61/62/63 dari history database.

    2. Pastikan add-on Nginx Proxy Manager benar-benar mendengarkan port 443 & 80 (uji dari Mikrotik: /tool fetch url="http://192.168.10.250:80").
    3. Cek di Mikrotik /ip firewall mangle, /ip firewall raw, dan pastikan akses tes dari jaringan luar (4G/5G) tidak terblokir ISP atau uji Hairpin NAT bila dari LAN.
    4. Wajib tambahkan blok http: use_x_forwarded_for: true + trusted_proxies + ip_ban_enabled: true di configuration.yaml agar terhindar dari 400 Bad Request.

10. Protokol Shoto TBD_BINARY, Audit EEPROM (13+43) & Pylontech 60H..63H

Hardware & ProtokolRE & Live Verified
  • TLV Biner 140 Byte (SD-BA430): Balasan 7E <addr> 01 86 ... 0D. DILARANG mengirim 16× 0xAA ke unit ini karena memicu balasan rusak (V=15.37V, SOC=2.0%).
  • Tag 0x02 & Tag 0x06: Arus memakai (30000 - raw) × 0.01f (+A = charge, -A = discharge). Tag 0x06 word 1 = 0x0002 adalah status discharging normal (dulu keliru dipetakan ke bit Cell-UV menyebabkan ALA 235 palsu; sekarang alarm diturunkan dari nilai sel/pack/suhu fisik).
  • Posisi Sel 61H: Memakai encoding desimal pack_id * 100 + cell_num agar solar.siseli.com tampil akurat ID:1(1) – ID:3(15).
  • Mengapa Remaining/Nominal Capacity & Cell Voltage 1..16 = 0 di solar.siseli.com? Karena pada Menu 05 = PYL, IHF6200 hanya polling 63H → 61H → 62H dan tidak pernah mengirim request V3.3 42H (bukan bug bridge; ke-15 sel per pack bisa dipantau penuh via Home Assistant View 2 atau Serial cells).
  • Audit EEPROM Read-Only (params & HA View 3): Membaca 13 register proteksi (cmd 0x06..0x50) dan 43 tag alarm (cmd 0x43, tag 0x00..0x2A, offset suhu -50 °C). Parameter terukur Shoto jauh di bawah 49–52 V (Pack UV alarm 42 V / cut-off 40 V / recovery 48 V; Low SOC alarm 20%/25%).
